# GenoSQL-Bench v2 — datasheet

A natural-language → SQL benchmark over public population-genomics data (chromosome 22, GRCh37),
scored by **execution accuracy**: gold and predicted SQL are both run and their results compared.

## Database

Seven tables built by `scripts/bootstrap.py` from public sources: 1000 Genomes phase 3 chr22
(`variants`, `genotypes` for alleles also in ClinVar, `samples`, `populations`), ClinVar 2026-10-11
chr22 (`clinvar`), Ensembl GRCh37 r87 chr22 genes (`genes`, `variant_genes`). Gold answers are only
valid against this exact build.

## How the generated items were made (`scripts/generate_benchmark.py`)

1. **Author** (`gemini-3.8-flash`; `gemini-3.1-flash-lite` when the free-tier daily quota ran out)
   receives the schema documentation and a *data card* of real values (genes, rsIDs, conditions,
   populations) and proposes questions with gold SQL and a lay paraphrase, per category.
2. **Automatic gates** — a proposal is rejected unless its SQL passes the SQL guard, executes,
   returns a small non-trivial result (not empty, not a lone 0/NULL, ≤ 30 rows), has no tie at a
   `LIMIT` boundary, and is not a near-duplicate (embedding similarity > 0.88) of an existing item
   or seed example. 284 proposals → 106 rejected (55 trivial, 21 empty, 22 near-duplicate,
   3 too many rows, 3 ties, 2 errors).
3. **Reviewer** (`gemini-3.7-flash`; `gemini-3-flash-preview` after its quota) — a *different*
   model — independently writes SQL from the question alone (it never sees the author's SQL), or
   declares the question unanswerable or ambiguous.
4. **Agreement** = the two queries return the same result (relaxed execution match; long/wide
   layouts equivalent; row order compared only when the question asks for one and the ranking
   key has no ties). Unanswerable items need the reviewer to decline independently.
   **Inter-annotator agreement: 92.1 % of 178 reviewed items** (88.8 % before fixing two comparator
   issues: the order-word detector matched "at least", and long vs wide layouts).
5. **Adjudication** (third annotator, notes in `generation/adjudication.jsonl`): 14 disputes →
   12 published with the reviewer's or a corrected query, 2 dropped (ambiguous; invented labels).
6. **Audit**: SQL-structure comparison against hand items and seeds → 3 exact duplicates excluded
   (one would have let RAG retrieve the answer); 3 same-template/different-entity items kept.
   One "between positions" item corrected to the hand-item reading (`pos BETWEEN`).

Published generated items: 173 = 144 execution-match agreements (6 after recheck) + 16 agreed
unanswerable + 13 adjudicated.

## Conventions encoded in gold SQL

Those of the schema documentation (`app/nl_query/schema.py`): `chrom = '22'`; rare < 1 %,
low-frequency 1–5 %, common ≥ 5 %; private = > 0 in one super-population and 0 in the others;
pathogenic = `is_pathogenic`; carriers = individuals (not allele copies); per-population
frequency = allele count / (2 × population size); "between positions" = `pos BETWEEN`,
"overlap" = interval overlap.

## Known limitations

- **LLM-written questions.** Phrasing is cleaner than real user questions; the lay paraphrases
  partially address this. A human expert review of a random sample is still recommended before
  publication (Phase 2 follow-up).
- **Annotators share a model family.** Author and reviewer are different Gemini versions, not
  independent humans; agreement may overstate validity where both share a misconception. They are
  a different family from the models under test (Qwen), avoiding self-preference.
- **Fallback author.** 66 published items come from a smaller author model after quota exhaustion;
  its proposals were rejected far more often (systematic wrong join key), but the gates and the
  reviewer apply equally.
- **Single chromosome, single release.** Answers are specific to this build.
- **Execution match is lenient on extra columns** (relaxed) and blind to label wording when the
  layout is long vs wide.
- **Prior exposure.** The 43 hand-written test items were inspected during v0/v1 development;
  the 105 generated test items were never inspected against model outputs. Report both
  (`eval.summarize --source generated|hand`).
